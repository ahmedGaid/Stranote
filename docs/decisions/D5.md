## Question 1 - the `X-EBS: 1` write header (PHASE_REVIEW C2)

Constitution §III says every write requires the `X-EBS: 1` header. The name is an EBS leftover; Phase I wants no
career words in the core. The header is used in `src/StranoteServer.ps1:117` and `src/dashboard_template.html:940,3088`.
Renaming it changes a constitution principle, so it needs an amendment (version bump, reason stated).

| Option | What changes | Cost / risk |
|---|---|---|
| A. Leave it | Nothing. Header stays `X-EBS` forever. | Zero risk; the core keeps one EBS word. |
| B. Amend §III to "a custom write header (today `X-EBS: 1`)", rename in Phase I | Constitution PATCH now. In Phase I the server accepts both `X-EBS` and `X-Stranote` for one release, then drops the old one. | Low. Old browser tabs and any script still work during the release. |
| C. Rename now | Amend §III and switch to `X-Stranote` immediately. | Medium: touches server, template and tests during Phase A; a stale open tab fails writes until reloaded. |

**Recommendation: B.** The principle (a custom header blocks cross-site form posts) does not depend on the name, so
the wording fix is cheap; the code rename belongs to Phase I where the other EBS names go. Unblocks: nothing urgent,
so it may wait until Phase I.

## Question 2 - what "inline payload < 150 KB" measures (PHASE_REVIEW U2)

The playbook section 4 budget says "Inline payload < 150 KB with 100 duties". PHASE_BASELINE.md measured:

| Boundary | Size | Passes 150 KB? |
|---|---:|---|
| Whole page (template + data) | 593079 B | No |
| Template alone | 283409 B | No (can never pass) |
| All inline JSON | 309727 B | No |
| Task JSON alone | 168914 B | No (close) |

| Option | Budget means | Effect |
|---|---|---|
| A. Whole page | Template + data < 150 KB | Impossible without a large template rewrite or split. Not realistic. |
| B. All inline data (JSON) | Tasks + learning + meta < 150 KB; a separate template budget (say < 350 KB) | Matches the playbook intent. Phase B lazy-loads `explain-ar`, lessons and history; learning JSON (132 KB) is the main lever. |
| C. Task JSON only | Tasks < 150 KB | Already near; hides the 132 KB learning payload. |

**Recommendation: B.** It measures what grows with the user's data and what Phase B can actually reduce. Record the
template size as its own budget so it cannot grow unnoticed.
